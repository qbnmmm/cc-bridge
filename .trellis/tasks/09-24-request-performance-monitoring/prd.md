# 请求性能监控与慢响应诊断

## Goal

让管理员定位模型请求为何需要三十多分钟才能回复：区分请求准备、等待上游、持续思考/生成、无有效内容进展和异常结束，并在请求尚未结束时发现长时间等待。

## Background

- 用户反馈 2026-09-24 响应特别慢，要求参考 sub2api 调研；调研提出性能概览、进行中请求、慢请求明细三个入口后，用户回复“可以，进任务吧”，授权创建 Trellis 任务、进入规划。
- 调研基线：cc-bridge `ccb / b2a0c21`；本地 sub2api `dbc8ae658cfc1c012160752582925e45115e2f3a`。尚未用生产请求记录确定当天慢响应的根因。
- 现有首字字段记录首个非空响应数据块（`src/service/usage.rs:576`），完整耗时观察主要用于自动遥测（`src/service/usage.rs:448`），用量事件不保存性能字段（`src/model/usage.rs:69`）。
- 现有 PERF_TRACE total 在返回流式 Response 时结束计时（`src/service/gateway.rs:386`）；读取空闲超时为 300 秒，持续心跳可能使长请求一直存活（`src/tlsfp/tlsfp.rs:324`）。

## Requirements

- R1 性能口径：分别展示首包、首个有效内容、首个正文、完整耗时、平均输出速度、无进展时长。心跳和元信息不算有效内容；思考和工具调用属于内容进展，但不冒充正文。
- R2 进行中请求：展示请求标识、账号、模型、当前阶段、已持续时间和最近有效进展距今时长；长请求未完成前即可查看。
- R3 历史明细：按日期、模型、账号、API Token、结果筛选，按耗时倒序查看；正常完成、失败、取消/释放、超时、断流以及无用量请求均有明确结果。无法确定的终态显示未知，不推断取消责任方。
- R4 性能概览：展示延迟 P50/P95/P99、最大值与样本数、有效输出速度、错误/取消情况和时间趋势；输出速度是单次生成期间的平均值，概览展示其样本中位数。缺失值不显示为零。
- R5 兼容性：采集独立于自动遥测和计费结果；保持响应字节、头、chunk 顺序、背压、限流和并发槽生命周期；监控故障不阻塞主请求。
- R6 观测边界：本期观测网关 API 请求；界面明确这是网关观测值，Agent 多轮任务、客户端工具执行和实际屏幕显示时间不属于完整覆盖范围。
- R7 覆盖与数据完整性：包含推理路径的鉴权失败/本地拒绝，其他接口不进入模型统计；监控缺口、未知结果及进程重启后的观测起点必须可见；不保存提示词、正文和凭证。
- R8 首版范围默认值（待整体方案评审）：只向管理员开放；性能历史保留 30 个新加坡自然日；进行中列表明确为当前实例范围，历史按所连接数据库查询；默认开启并可关闭采集。

## Acceptance Criteria

- [x] AC1 / R1：先返回心跳或 message_start、稍后才返回思考和正文时，各时间点可区分，心跳不刷新有效内容进展。
- [x] AC2 / R2：持续心跳但无内容的请求，在结束前可看到增长的请求年龄和无进展时长。
- [x] AC3 / R3：成功、上游发送失败、限流、流内错误、中途断流、客户端取消和无 usage 都可查询，HTTP 200 不自动代表流完整成功。
- [x] AC4 / R4：聚合值与明细样本一致；不同模型/账号可筛选；进行中、失败和缺失首正文的请求不被计作零延迟成功样本。
- [x] AC5 / R5：关闭自动遥测仍可监控；监控写入失败/队列满不改变主响应；原有计费、SSE/compression 和 slot 生命周期回归通过。
- [x] AC6 / R6：管理员可利用阶段耗时区分网关准备慢、首内容慢、生成慢和中途停顿；不宣称能据此精确区分上游排队与预填充，或覆盖完整 Agent 任务。
- [x] AC7 / R7：鉴权/本地失败可记录空维度，监控队列满或解析失败有健康提示；无 Token 凭证、提示词和正文落库；取消责任不明时不误报客户端故障。
- [x] AC8 / R8：未认证无法查询性能数据；过期性能数据被清理且不影响既有用量历史；当前实例标识可见；关闭采集停止新增记录，已有历史仍可查询。

## Out of Scope

- 本期不新增自动重试、切号、自动断流或修改上游超时策略。
- 本期不引入外部监控平台、消息通知渠道、客户端埋点或完整会话链路追踪。
- 不补造历史请求性能数据，不存储提示词、响应正文或凭证。
