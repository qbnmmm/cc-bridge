# 优化用量趋势图数据点显示

## Goal

改善管理端用量趋势图在宽屏和短时间范围下的可读性：数据点保持清晰的圆形，并在当前范围数据点过少时为趋势图提供足够的前序历史上下文。

## Background

- 2026-08-25 的页面截图显示，本周仅有 2026-08-24、2026-08-25 两个日点，趋势线横跨整张图，难以判断近期变化。
- 本月趋势图的数据点在宽屏下被横向拉伸成扁椭圆。
- `web/src/components/usage/UsageTrend.vue` 使用 `preserveAspectRatio="none"` 拉伸 SVG，同时直接绘制 `<circle>`，因此宽高缩放比例不同会让圆点发生形变。
- `web/src/lib/usage.ts` 中“本周”严格从周一开始、“本月”严格从当月 1 日开始；在周/月初选择日粒度时，报告可能只有少量 bucket。
- 当前同一份 `UsageReport` 同时驱动汇总、趋势和拆分；若直接扩大主查询日期，汇总和拆分口径也会随之改变。

## Requirements

- R1. 趋势图的数据点在不同容器宽度下必须保持视觉上的圆形，不得随 SVG 非等比缩放变成扁椭圆。
- R2. 首尾数据点应完整可见，不应被图表边界裁切。
- R3. 日粒度下，所选范围少于 7 个趋势点时，趋势图应向前补入真实历史日数据，尽量达到最近 7 个点，避免只有一两个点占满整张图。
- R4. 补入的历史上下文不得改变页面顶部汇总和下方拆分表的所选日期统计口径。
- R5. 保持现有 Token/USD 切换、tooltip、键盘聚焦和响应式布局，不引入大型图表依赖。

## Acceptance Criteria

- [x] AC1. 在宽屏桌面布局中，本周和本月趋势点均显示为圆形，hover/focus 后仍为圆形。
- [x] AC2. 第一个和最后一个趋势点完整显示在绘图区内。
- [x] AC3. 日粒度少于 7 个所选范围内数据点时，趋势图向前补入真实日数据并尽量达到 7 个点；本周或本月在周期初只有 1–2 天时仍能形成可读走势。
- [x] AC4. 额外趋势上下文不会计入请求数、总 Token、成本、Token 分类或拆分表。
- [x] AC5. 自定义日期、周/月聚合及接近 365 日保留边界时不会请求非法日期；无法继续向前补点时仍正常展示已有数据。
- [x] AC6. `cd web && npm run build` 通过。

## Out of Scope

- 修改用量事件采集、成本计算或数据库聚合口径。
- 引入第三方图表库或重做整个用量页面视觉设计。

## Confirmed Product Decision

- 仅在日粒度下补点，目标为最近 7 个真实日数据点。补点只影响趋势图，不改变所选范围的汇总和拆分统计。
